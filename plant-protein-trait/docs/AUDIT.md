# Audit and migration from the supplied pipeline

The seven Python files in the supplied archive were read in full before implementation. Their SHA256 hashes, byte counts and line counts are retained in [original_source_manifest.json](original_source_manifest.json). No additional local implementation module existed in that archive; `prepare_sequences.py` referred to a missing placeholder module. External dependencies and tools were not bundled.

This release is a **scoped single-protein refactor**, not a claim that the original scripts were successfully run, and not a drop-in replacement for every historical CLI flag. The scientific analysis follows the `new_llm.py` lineage. The older `llm.py` was used only to understand inherited behavior. Raw legacy source copies, private hard-coded paths and embedded contact details are not republished.

## Observed data flow

The archive was not one fully connected orchestrator. `4_cotton.py` cleaned FASTA, attempted BLAST and domain annotation, computed heuristic scores, optionally read predicted PDBs and exported annotation files. `new_llm.py` separately collected evidence snippets and requested model output. Structure helper scripts were separate preprocessing utilities; they did not predict structures. `final.py`/ranked outputs referenced in the inference code were not supplied or generated by `4_cotton.py`.

## Findings and resolution

| Original location | Observed problem | Release behavior |
| --- | --- | --- |
| `new_llm.py`, verify/explore/evidence/system prompts, approximately lines 956–1246 and 1428–1449 | Unconditional two-protein relationships, isoform differences, synergy and splicing mechanism requirements remain with one sequence | Dedicated single-protein protocol; no fabricated second query; explicit claim grades |
| `new_llm.py`, lines 706–772 | Record loader expects ranked/final outputs, whereas the annotation code exports a sequence-ID-keyed dictionary | Direct `annotation_full.json` loading, exact query selection, aliases and structure sidecar support |
| `4_cotton.py`, lines 493–520 | Summary TSV mostly stores scores, not rich function evidence | Full JSON is authoritative; score-only input is rejected |
| `new_llm.py`, lines 537/555/576 | JSON/text context is truncated to a character count and may cease to be valid JSON or omit evidence | Parse complete source; canonical allowlisted packet; fail on configured prompt limit rather than truncate |
| `new_llm.py`, lines 131–171 | FASTA header is attached to the wrong record or lost | Strict one-record parser retains the actual header and hashes the sequence |
| `new_llm.py`, lines 175–409 | Similarity threshold treated as isoform detection; formatted alignment text used for identity; peptide differences overinterpreted as splicing | Multi-isoform inference removed from supported scope; one sequence cannot establish splicing consequences |
| `new_llm.py` and `llm.py`, prompt grading | Enzyme/family annotation can be upgraded to “certain” function; strong pressure to complete a causal narrative | Computational annotations are not direct experiments; insufficient/unknown output accepted |
| `new_llm.py`, lines 1496 onward | Provider errors written as output reports; program can still finish as if successful | Failure state and nonzero exit; retain raw output; no frozen success for errors |
| `4_cotton.py`, lines 96, 118–144, 561–569 | Stops silently deleted; remote database fixed to nr; individual XML files written but nonexistent combined XML parsed | Stops rejected; database explicit; parse the exact saved result file |
| `4_cotton.py`, lines 160–168 | Raw score does not expose bit score; coverage uses alignment length and may exceed query coverage due to gaps | Best-HSP bit score/identity/query-coordinate coverage; separate union coverage; raw HSPs retained |
| `4_cotton.py`, lines 595–597, 651–676 | Remote results wrapper not normalized; GO commonly nested under signature entry is missed; arbitrary counts used as evidence scores | Exact-sequence InterPro record extraction and nested GO extraction; no aggregate confidence score |
| `4_cotton.py`, lines 763–769 | Missing structural analysis is replaced with a sequence/domain proxy structure score | Missing target structure stays null and explicit; legacy proxy excluded |
| `4_cotton.py`, lines 313–327 | Average B-factor includes all atoms and may be confused with pLDDT for arbitrary PDBs | New AFDB path only; one CA per residue; full query binding; explicit predicted-model provenance |
| `4_cotton.py`, structural helpers | Report advertises self-match protection not actually implemented; experimental PDB B-factors can be misinterpreted; RCSB mapping path questionable | Automatic arbitrary PDB/TM ranking excluded from this release; no unverified structure claims |
| `4_cotton.py`, module initialization | Creates directories and imports sklearn even when ML is unused | Standard-library core; no side effects on import; ML scoring removed from supported scope |
| `1_afdb_seq_search_download.py` | Swiss-Prot hits are accession-sorted rather than ranked; old polling can miss completed XML and undercount wait time; fixed AFDB fallback versions; homolog downloads risk being treated as query models | Separate BLAST statistics; bounded compliant polling; AFDB API URL; exact full-length sequence match required |
| `2_af3_cif_to_pdb.py` | Hard-coded server paths; fixed extraction directory; flat basenames may overwrite models; no structure prediction actually performed | Conversion is not necessary for the direct AFDB path; utility omitted from supported runtime |
| `3_map_af3_pdbs.py` | Hard-coded paths; PPBuilder may omit isolated residues; chain suffixes not recognized by downstream search; symlink assumptions | No automatic renaming of homolog models as target models; direct target-bound structure retrieval |
| `prepare_sequences.py` | Imports nonexistent `your_main_script`; directory handling incomplete; approximate molecular mass could be mistaken for a precise measurement | `check_sequence.py` performs explicit QC; obsolete comparison preparation removed |
| `llm.py` | Older comparison prompts, same final-report coupling and escaped newline artifacts | Historical audit reference only; not used as the inference engine |

## CLI migration

| Old usage | New usage |
| --- | --- |
| `4_cotton.py -i ... -o ...` | Still accepted as aliases for FASTA and output |
| Automatic remote nr fallback | Explicit `--online-blast --remote-database swissprot --email ...` |
| Automatic InterProScan contact from code | Explicit `--interpro-remote --email ...`, or `--interpro-json ...` |
| `--af3-pdb-dir` / `--pdb-lib-dir` | Not supported by the new collector; use exact target `--afdb-accession` if available |
| `--with_struct_dir --final_dir` | Removed; `--annotation-dir` consumes real annotation output |
| `--out_description --out_evidence` | Replaced by a run directory with immutable per-slot JSON, raw response and report |
| `--trait` inside a single model request | `prepare --trait ...` creates isolated targeted and blind prompt sets |
| `report/inference` mode aliases | Explicit `verify`/`explore`; both generated by preparation |
| Inline `--api_key` | Environment-only credentials |
| `prepare_sequences.py` | `scripts/check_sequence.py` |

## Deliberate limitations

Version 0.1.0 supports the single-protein function-to-trait task. It does not implement isoform comparison, de novo structure prediction, live Foldseek/TM-align, genome/CDS source reconstruction, machine-learning score models or remote-job automatic resumption. These are documented exclusions, not silently reported as successful stages. The optional structure route and two remote annotation clients require live validation in the deployment environment. Offline parser tests and mocked model calls are not evidence of real service execution.
